Sprint ใน Agile ทำงานอย่างไร ให้เกิดผลจริง ?

รอบการทำงานสั้นๆ ที่ส่งมอบ "ชิ้นงานที่ใช้งานได้จริง (Shippable Increment)" สม่ำเสมอ
MISSION

1. THE SPRINT HEARTBEAT : จังหวะการเต้นของทีม Agile

  • 1Sprint คือกรอบเวลาคงที่ (Time-box) ที่ทีมมีสมาธิโฟกัสกับเป้าหมายเดียวที่ตกลงร่วมกัน
  • 2ผลลัพธ์ตอนจบ Sprint ต้องเป็นชิ้นงานที่ผ่านการทดสอบและพร้อมใช้งานได้จริง (Potentially Shippable)
  • 3ช่วยให้ได้รับ Feedback จากผู้ใช้และตลาดอย่างรวดเร็วเพื่อนำมาปรับทิศทางในรอบถัดไป
  • 4ช่วยลดความเสี่ยงจากการพัฒนาโครงการยาวนานหลายเดือนโดยไม่มีการตรวจสอบ

CHARACTER × CAPABILITY
Sprint Goal

Sprint Goal (เป้าหมายหนึ่งเดียว)

เหตุผลสำคัญว่าทำไมเราถึงต้องทำ Sprint นี้ เพื่อให้ทีมมีโฟกัสร่วมกัน

Capacity

Capacity & Commitment (ความพร้อมจริง)

คำนวณวันลา วันหยุด และแรงงานจริงก่อน Commit งานเข้าสู่กระบวนการ

DoD Gate

Definition of Done (มาตรฐานความเสร็จ)

โค้ดผ่าน, เทสผ่าน, ผ่าน Code Review, และ Deploy บน Staging สำเร็จ

CLARITY CHECK
  • เปลี่ยน Sprint Goal หรือเพิ่มงานแทรกโดยไม่ตัดงานเก่าออก
  • ปล่อยให้มีคนแอบสั่งงาน Dev นอกรอบโดยไม่ผ่าน PO
  • ตัดขั้นตอนการทำ Automated Test หรือ QA เพื่อเร่งงาน
  • ไม่ยอมยกมือบอกปัญหาใน Daily Scrum จนถึงวันสุดท้าย
Sprint ที่มีประสิทธิภาพช่วยลดความเครียดของทีม และส่งมอบสิ่งที่มีคุณค่าให้แก่ลูกค้าอย่างต่อเนื่อง
KEY TAKEAWAY
Sprint สำเร็จ = ล็อก Sprint Goal + โฟกัสสร้างงานจริง + ซิงก์รายวัน + DoD ผ่าน 100% + ปรับปรุงทีมทุกรอบ
