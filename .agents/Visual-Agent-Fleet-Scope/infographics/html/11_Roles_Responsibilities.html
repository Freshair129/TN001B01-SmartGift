1. RACI FRAMEWORK : ชัดเจนในทุกความรับผิดชอบ

  • 1Accountable (A) : ผู้รับผิดชอบผลลัพธ์ขั้นสุดท้าย มีอำนาจตัดสินใจเด็ดขาด (มีได้เพียง 1 คนต่องาน)
  • 2Responsible (R) : ผู้ลงมือปฏิบัติงานจริงเพื่อให้งานสำเร็จตามเป้าหมาย
  • 3Consulted (C) : ผู้เชี่ยวชาญที่ต้องขอคำปรึกษาและข้อคิดเห็นก่อนตัดสินใจ
  • 4Informed (I) : ผู้ที่ต้องได้รับการแจ้งข่าวสารและสถานะความคืบหน้าอย่างต่อเนื่อง

CHARACTER × CAPABILITY
PO + PM

PO & PM (คู่หูยุทธศาสตร์)

PO ดูแล 'คุณค่าและความคุ้มค่า' ส่วน PM ดูแล 'เวลาและทรัพยากร' เพื่อผลักดันโครงการ

BA + Dev

BA & Dev (คู่หูถ่ายทอดโจทย์)

BA ถ่ายทอดโจทย์ธุรกิจและ Flow ส่วน Dev แปลงเป็น Solution และสถาปัตยกรรมระบบ

Dev + QA

Dev & QA (คู่หูคุณภาพซอฟต์แวร์)

ร่วมกันตรวจเช็ก AC ดักจับ Edge Cases และทดสอบระบบก่อนส่งมอบสู่ผู้ใช้

CLARITY CHECK
  • ให้ BA ตัดสินใจทิศทางธุรกิจแทน PO โดยพลการ
  • โยนหน้าที่การบริหารเวลาทั้งหมดให้ Dev รับผิดชอบ
  • มองว่า QA เป็นคนเดียวที่ต้องรับผิดชอบเรื่องคุณภาพ
  • ต่างคนต่างทำงานในไซโลโดยไม่มีการสื่อสารข้ามสายงาน
การแบ่งหน้าที่ที่ชัดเจนไม่ได้สร้างกำแพงกั้น แต่ช่วยให้ทุกคนรู้จุดโฟกัสและส่งพลังเสริมกันได้อย่างเต็มที่
