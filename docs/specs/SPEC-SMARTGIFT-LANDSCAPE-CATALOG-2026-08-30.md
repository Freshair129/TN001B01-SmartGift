# SmartGift Landscape Catalog: ข้อเสนอรูปแบบและแผนเนื้อหา

## 1. เป้าหมายและสถานะ

ออกแบบ catalog ของ SmartGift สำหรับลูกค้าองค์กร โดยใช้แนวทางการจัดภาพจาก [FlipHTML5 ที่ผู้ใช้ระบุ](https://online.fliphtml5.com/xgczt/qizk/#p=51) และแนวคิดจาก `data-pipeline/01_raw/06_business_pdf/` จัดหน้าใหม่เป็น **A4 แนวนอน 297 × 210 มม. แบบหนึ่งหน้าต่อหนึ่งหน้า PDF**

**C-2 / Risk MEDIUM สำหรับการผลิตภาพและ PDF:** ผู้ใช้ยืนยันเมื่อ 2026-08-30 ให้ใช้ภาพสินค้าจริงจาก catalog มา gen เป็น ad creative ในแต่ละ set และสินค้าเดี่ยวหน้าละ 2-3 รายการ จึงดำเนินงานภาพ/เอกสารตามขอบเขตนี้ได้ โดยไม่เปลี่ยน application code, schema, pipeline, master data, ราคา หรือ vault

เอกสาร peer ของหน้าเว็บยังเป็น candidate และไม่ใช่การอนุมัติเปลี่ยนเว็บ งานที่ยืนยันในฉบับนี้เป็นการผลิต catalog assets/PDF ไม่ใช่ application implementation จึงไม่ขออนุมัติแนวทางภาพและความหนาแน่นหน้าซ้ำ

ความสำเร็จของงาน: ลูกค้าดูภาพแล้วรู้ว่าเป็นของอะไร เหมาะกับการให้ในบริบทใด และในชุดได้รับอะไร โดยอ่านภาษาไทยง่าย ไม่มีข้อมูลภายในหรือราคา/คำรับรองที่ไม่มีหลักฐาน

[ASSUMPTIONS]

1. ใช้ reference เพื่อศึกษาลำดับการอ่านและ grid ไม่คัดลอกภาพสินค้า โลโก้ลูกค้า ชื่อชุด ราคา หรือข้อความของเจ้าของต้นฉบับ
2. PDF concept เป็นแหล่งแนวคิด ส่วนภาพต้นแบบสินค้าใช้ catalog สินค้าจริงที่ตรวจรหัส/ภาพ/ข้อความตรงกัน ไม่ใช้สไลด์ concept เป็นภาพตั้งต้นแทนสินค้า และไม่ใช้ภาพที่ gen เป็นหลักฐานสเปกหรือใบรับรอง
3. A4 แนวนอนและเล่มเป้าหมาย 24 หน้าเป็นข้อเสนอเริ่มต้น ยังไม่ใช่ข้อกำหนดโรงพิมพ์ที่ผู้ใช้ยืนยัน จำนวนสุดท้ายต้องสอดคล้องกับภาพ/สินค้า/รายละเอียดที่ตรวจยืนยันได้ ไม่เติมรายการเพื่อให้ครบหน้า
4. เล่มเน้นภาพจริง ไทยเป็นหลัก ใช้ชื่อภาษาอังกฤษของหมวดและ tier คู่กัน ไม่มีใบเสนอราคาเฉพาะลูกค้า ไม่มีรายชื่อผู้รับ ไม่มีการเผยแพร่ภายนอกในงานนี้

## 4. แนวทางออกแบบที่เสนอ

**แนวคิด: “ของขวัญที่เริ่มจากผู้รับ”**

นำ Recipient-first, ความพรีเมียมที่พอดี และการออกแบบประสบการณ์แกะกล่องมาเล่าให้ลูกค้าเข้าใจผ่านภาพ การเลือกสิ่งของ และรายละเอียดวัสดุ ไม่ใช้ศัพท์ฐานข้อมูล/AI/สถาปัตยกรรมเป็นเนื้อหาขาย

- อารมณ์: สงบ ชัดเจน พิถีพิถัน ภาพเด่น พื้นที่ว่างพออ่าน ไม่มีตารางเทคนิคแน่นทุกหน้า
- สีเสนอ: warm paper `#F7F5EF`, ink `#182B30`, petrol `#08798A`; สีวัสดุธรรมชาติเป็นสีรอง ไม่สร้างสีแบรนด์หลายชุดตาม tier
- ตัวอักษรเสนอ: Noto Sans Thai สำหรับไทย/ละติน หรือฟอนต์ที่มีสิทธิ์ embedding เหมาะสม ตรวจ glyph ไทย วรรณยุกต์ น้ำหนัก และการตัดบรรทัดก่อน export; ไม่อ้างว่าเป็น CI ที่อนุมัติแล้ว
- ใช้ชื่อ SmartGift เป็นข้อความในรอบ mockup ไม่ถือโลโก้ในสไลด์สร้างภาพหรืออักษร SG ของเว็บเป็นไฟล์ตราสัญลักษณ์พร้อมพิมพ์
- หน้าเซ็ตใช้ ad creative ขนาดใหญ่ที่สร้างจากภาพจริงของเซ็ตนั้น เก็บรูปทรง สี วัสดุ รายละเอียด และของในชุดให้ตรงต้นฉบับ เปลี่ยนฉาก แสง และการจัดองค์ประกอบได้; สินค้าเดี่ยวจัดเพียง 2-3 รายการต่อหน้า ไม่ใช้ grid 6 รายการ
- ขนาดตัวอักษรเป้าหมาย: headline 28-40 pt, section 20-28 pt, body 10.5-12 pt, caption 9-10 pt; ตรวจพิมพ์จริงที่ 100% และไม่ลดขนาดเพื่อฝืนให้ข้อความพอดี
- grid 12 คอลัมน์, outer margin 14 มม., gutter 5 มม., inner/binding allowance 18 มม. เป็นค่าตั้งต้นและต้องปรับตามการเข้าเล่ม; เนื้อหาสำคัญไม่ชนแนวตัด

### หมวดและ tier

ใช้ [ADR-001 ที่อนุมัติแล้ว](../decisions/ADR-001-ECO-FRIENDLY-CATEGORY-REFACTOR.md) เป็น authority เหนือหมวดเก่าในสไลด์:

|---|---|
| Tech & Work / เทคโนโลยีและการทำงาน | `executive-smart-tech` |
| Wellness & Care / การดูแลตัวเอง | `novelty-self-care` |

### หน้าต้นแบบสำหรับตรวจแนวทาง

รอบนี้มีตัวอย่างในบทสนทนา 4 หน้า: **ปก / เปิดหมวด / 2 ชุดสินค้า / Unboxing** เป็น design proof ใช้กรอบภาพที่ระบุว่ารอภาพจริง และใช้ diagram ของกล่องที่ระบุว่าเป็นแนวคิด ไม่มีราคา SKU หรือคำรับรองพร้อมขาย ไม่ใช่ final PDF

หลังอนุมัติให้สร้าง PDF proof จากข้อมูลที่ตรวจแล้วก่อน ใช้ผลตรวจแก้ตัวเล่มต่อได้ภายในขอบเขตที่อนุมัติ ไม่ต้องเปลี่ยน schema หรือแก้ระบบเพื่อทำ catalog

## 6. สัญญาเนื้อหาสำหรับแต่ละรายการ

หน้าสินค้าเดี่ยว: ภาพต้นฉบับ/ภาพที่ตรวจความตรงแล้ว → ชื่อ → รหัสสำหรับคุยกับทีมขาย → รายละเอียดสั้น → วัสดุ/ขนาดที่ยืนยัน; หนึ่งหน้ามี 2-3 สินค้าเท่านั้น

หน้าชุด: ad creative ของเซ็ตนั้น → ชื่อชุด → “ในชุดประกอบด้วย” + จำนวนที่ยืนยัน → ทางเลือกปรับแต่งที่ยืนยัน → สถานะราคา

### ขั้นผลิต ad creative ที่ผู้ใช้ยืนยัน

1. เลือกเซ็ตจาก catalog จริง ตรวจภาพกับรหัสและข้อความในหน้าเดียวกัน เก็บ source page/hash ภายใน และครอบเฉพาะสินค้าออกจากราคา/ข้อมูล supplier โดยไม่แก้ PDF ต้นทาง
2. ส่งภาพสินค้านั้นเป็น edit target/reference ให้ built-in image_gen เปลี่ยนฉาก แสง เงา และองค์ประกอบโฆษณา สร้างแยกทีละเซ็ต ห้ามอาศัยชื่อสินค้าอย่างเดียวหรือใช้ภาพเซ็ตอื่นแทน
3. ล็อกรูปทรง สี ผิววัสดุ โลโก้ที่เป็นส่วนหนึ่งของผลิตภัณฑ์ ตำแหน่งอุปกรณ์ และจำนวนชิ้น ไม่เพิ่มสินค้าที่ไม่ได้รวม ไม่สร้างแบรนด์/สเปกใหม่ ไม่ใส่ข้อความราคาในภาพ
4. หากมีโลโก้ลูกค้า/supplier ที่ไม่ได้อนุญาต เลือก source ที่ไม่มีตรานั้นหรือระบุสถานะ reference; ไม่ลบแล้วทำให้เข้าใจว่าเป็นงานลูกค้า SmartGift
5. ตรวจ generated image เทียบต้นฉบับแบบข้างกันทุกเซ็ต หากจำนวนชิ้น รูปทรง หรือรายละเอียดสำคัญเปลี่ยน ให้แก้ภาพ/คัดทิ้ง ไม่ผ่านเพียงเพราะสวยขึ้น
6. ภาพที่ gen ใช้ label “ภาพสร้างสรรค์จากภาพสินค้าอ้างอิง” และไม่เรียกว่าเป็นภาพถ่ายสินค้าจริง; ฉาก/props ถ้ามีต้องแยกจากรายการในชุดอย่างชัดเจน ข้อความจริงจัดใน PDF แยกจากภาพ
7. เก็บภาพต้นแบบ ภาพผลลัพธ์ prompt และผลตรวจเป็นไฟล์งานภายใน แยกจาก PDF สำหรับลูกค้า การ gen ไม่เพิ่มความพร้อมด้านราคา/stock/claims

เมื่อ canonical components หรือ media mapping ขัดกับภาพ/ข้อความต้นฉบับ ให้ใช้หลักฐาน PDF ของรหัสเดียวกันสำหรับฉบับ proof และบันทึกข้อจำกัด ไม่แก้ฐานข้อมูลในงานนี้ และไม่อนุมานของในชุดจาก master ที่ขัดกัน

- ก่อนใช้ภาพ ต้องตรวจ `source file + page + source code + target SKU/offer + crop` และ hash ต้นทาง/ภาพให้ย้อนตรวจได้ บันทึกเฉพาะ product lineage ใน manifest สำหรับทีมงานภายใน ไม่ใส่ customer data และไม่ฝัง provenance ลงในเล่มลูกค้า
- รูปจาก NotebookLM/concept PDFs ไม่ใช่หลักฐานภาพ SKU; ไม่แก้ watermark แล้วนำมาอ้างว่าเป็นภาพสินค้าจริง ถ้าจะใช้ illustration ต้องมีสิทธิ์ใช้และมี label ตามจริง
- ไม่เดา BOM จากภาพ ไม่เติมจำนวนชิ้น MOQ lead time stock วัสดุ หรือรายละเอียดจากชื่อชุด
- ราคาต้องอ้าง FlowAccount export + pricing calculator ตาม AGENTS พร้อมหน่วย จำนวนที่ใช้คิดราคา และ validity ถ้ายังยืนยันไม่ได้ใช้ **“สอบถามราคา”** เป็นข้อความ ไม่ใช้ 0 บาท หรือราคา “เริ่มต้น” ที่ไม่มี basis
- ในฉบับเผยแพร่ต้องไม่มี placeholder, watermark “draft”, หรือ SKU ที่ยังจับคู่ไม่สำเร็จ; ถ้ารายการข้อมูลไม่ครบให้ตัดออกหรือส่งเป็น proof ที่ระบุข้อจำกัด ไม่เรียกว่าเล่มสมบูรณ์
- ห้ามมีต้นทุน กำไร supplier contacts รหัสโรงงาน CBM ค่าขนส่งภายใน รายชื่อลูกค้า quotation history ชื่อผู้รับ หรือตัวเลขยอดขาย
- ไม่ใส่โลโก้/คำรับรองจากลูกค้าโดยไม่มีสิทธิ์และหลักฐาน ไม่ใช้ medical, battery/flight-safe, ESG/recycled หรือ environmental claims จาก concept เป็นข้อเท็จจริงสินค้า
- โลโก้ SmartGift และช่องทางธุรกิจต้องมาจาก asset/ข้อมูลที่ยืนยันสำหรับเผยแพร่ ไม่ดึงข้อมูลติดต่อจากเอกสาร CRM

## 7. มาตรฐาน PDF และไฟล์ส่งมอบหลังอนุมัติ

| หัวข้อ | Digital PDF | Print PDF |
|---|---|---|
| ขนาดตัดสำเร็จ | 297 × 210 มม. A4 landscape ทุกหน้า | TrimBox 297 × 210 มม. |
| การจัดหน้า | Single pages, ไม่ใช่ facing spreads | Single pages ให้โรงพิมพ์ impose |
| ขอบตัดตก | ไม่มี crop marks/bleed ที่รบกวนการอ่าน | เสนอ bleed 3 มม. รอบด้าน; ขนาดรวม bleed 303 × 216 มม. ไม่รวม marks; ยืนยันกับโรงพิมพ์ |
| สี | sRGB สำหรับดูบนจอ | Color-managed ตาม ICC/output condition ที่โรงพิมพ์ยืนยัน; ไม่แปลง CMYK แบบเดา profile |
| ภาพ | เป้าหมาย 150-200 ppi ตามขนาดวางจริง | เป้าหมายภาพถ่าย 300 ppi ตามขนาดวางจริง; ไม่ถือการ upscale ว่าเพิ่มรายละเอียดต้นฉบับ |
| ตัวอักษร | Embedded fonts, selectable/searchable Thai text | Embedded fonts ที่มีสิทธิ์ใช้งาน; ตรวจ glyph/overprint |
| การใช้งาน | Bookmarks, clickable contents และช่องทางติดต่อที่ยืนยัน | ไม่มี controls/flip animation; marks ตามข้อกำหนดโรงพิมพ์ |
| สถานะมาตรฐาน | PDF สำหรับอ่าน/แชร์ ไม่อ้าง PDF/X หรือ PDF/UA โดยไม่ตรวจ | เป้าหมาย PDF/X-4 เมื่อมี output intent และผ่าน preflight จริง |

อ้างอิงมาตรฐาน: [Adobe PDF export options](https://helpx.adobe.com/indesign/desktop/save-export-and-publish/save-and-export/adobe-pdf-export-options.html) แยกการตั้งค่า compression, marks/bleed, output intent และ fonts; [PDF Association: PDF/X key facts](https://pdfa.org/pdfx-the-key-facts/) อธิบาย embedded fonts, ICC output intent และ page boxes. **A4/300 ppi/bleed เพียงอย่างเดียวไม่ใช่หลักฐานว่า PDF ผ่าน PDF/X-4**

ผลลัพธ์ที่เสนอภายใต้ `output/pdf/`:

1. `smartgift-catalog-2026-digital.pdf` พร้อมรายงานจำนวนหน้า/สินค้าที่ครอบคลุม
2. `smartgift-catalog-2026-print-proof.pdf` หากยังไม่มี printer profile/preflight ให้ติดสถานะ proof ไม่เรียก print-ready
3. เปลี่ยนเป็น `smartgift-catalog-2026-print.pdf` เฉพาะเมื่อผ่านสเปกโรงพิมพ์และ preflight พร้อมแนบผลตรวจ
4. source layout ที่แก้ไขได้และ product-only source/page mapping สำหรับบำรุงรักษา เก็บเป็น **internal-only** ใน `output/catalog-internal/` แยกจาก `output/pdf/` ไม่ส่งให้ลูกค้าและไม่แนบ/ฝังใน PDF โดยไม่เพิ่ม field เข้า master/pipeline/vault

การอนุมัติสเปกนี้ไม่รวมการสั่งพิมพ์ อัปโหลด FlipHTML5 deploy เว็บ commit/push หรือส่งข้อมูลให้บุคคลภายนอก

## 9. แผนผลิตและเกณฑ์ตรวจรับ

1. ตรวจไฟล์ล่าสุดและจัดทำรายการเนื้อหา/ภาพจริงแบบ product-only โดยไม่แก้ raw หรือ data model → ทุก SKU/offer มี lineage และสิทธิ์ใช้ภาพ
2. สร้าง ad creative ต่อเซ็ตด้วย image_gen และจัดหน้าใหม่; โซนสินค้าเดี่ยว 2-3 รายการ/หน้า → ชื่อ/ภาพ/รายละเอียด/ของในชุดตรงรายการ; ไม่มีข้อมูลเดา
3. ผลิต Digital PDF ครบขอบเขตที่มีหลักฐาน → ตรวจ page count, page dimensions, embedded fonts, selectable Thai text, bookmarks/links และจำนวนรายการที่ครอบคลุม
4. Render ทุกหน้าเป็นภาพและตรวจที่ 100% พร้อม contact sheet → ไม่มีข้อความทับ/ตกขอบ วรรณยุกต์ผิด รูปบิด รูปแตก หรือเลขหน้าผิด; รูปทุกหน้าตรงกับ source mapping
5. ตรวจ PII/ต้นทุน/claim/metadata/attachments ทั้งเล่มด้วย text extraction และ visual inspection; รูป raster ต้องตรวจด้วย ไม่พึ่ง text scan อย่างเดียว → ไม่มีข้อมูลต้องห้าม และไม่มี source path/hash/provenance/supplier identity ในข้อความ metadata หรือ attachments ของ PDF ลูกค้า
6. ถ้ามีสเปกโรงพิมพ์ ให้ผลิต print version และ preflight → Trim/BleedBox, output intent, font embedding, image resolution และข้อกำหนดโรงพิมพ์ผ่านก่อนเรียก print-ready
7. ตรวจ hash ต้นทางและ working-tree diff เทียบก่อนงาน → raw, app code, masters และ vaults ไม่เปลี่ยน; รักษางานที่มีอยู่ก่อน

รอบเอกสารไม่แก้ domain logic จึงไม่ต้องรัน unit suite หรือ master pipeline; การตรวจที่เกี่ยวข้องคือความถูกต้องของแหล่งอ้างอิง metadata/version ขอบเขตข้อมูล และการแสดงโครงหน้า

ผลตรวจรอบเอกสาร: local references 7/7 resolve ได้, source SHA-256 5/5 ตรงกับก่อนงาน, ไม่มี trailing whitespace; Browser ตรวจปุ่มสลับหน้า 4/4 และไม่พบ horizontal/text overflow ที่ความกว้าง 736 และ 360 px. จอเล็กปรับโครงหน้าให้เรียงลงสำหรับดูตัวอย่าง ไม่ใช่การเปลี่ยนขนาด PDF จริง. ข้อทักท้วงจาก review เรื่องแยก internal provenance ออกจากไฟล์ลูกค้าแก้แล้วตามข้อ 6, 7 และ 9.5. ผลนี้ไม่ใช่การตรวจ final PDF หรือ PDF/X preflight

**Exit การผลิต:** ส่งภาพ ad creative และ landscape PDF ที่ตรวจจริง พร้อมระบุ coverage และข้อจำกัด หากยังไม่ได้ตรวจ commercial rights/stock/print preflight ให้เรียก proof ไม่ใช่ catalog พร้อมเผยแพร่หรือ print-ready

## 10. Approval และสิ่งที่ยังต้องยืนยันก่อนใช้จริง

คำสั่งผู้ใช้ 2026-08-30: “ภาพสินค้า เอาภาพจริงจาก catalog มา gen ใหม่ เป็นงาน adcreative ในแต่ละset ส้วนโซนสินค้าเดี่ยว หน้านึง มี 2-3 product พอ” ยืนยันวิธีผลิตภาพและความหนาแน่นหน้าตามข้อ 6 โดยคง A4 landscape และแนวคิดเดิม ไม่ใช่การอนุมัติราคา/claims/stock หรือ public publication; 24 หน้าเป็นเป้าหมายเชิงบรรณาธิการ ปรับตามรายการที่ตรวจยืนยันได้

ยังต้องตรวจหรือรับข้อมูลก่อน final: ภาพ/สินค้าที่นำเสนอได้จริง, asset โลโก้, ช่องทางธุรกิจสำหรับปกหลัง, สิทธิ์ภาพ/claims และสเปกโรงพิมพ์/ICC หากต้องการ print-ready. เมื่อยังไม่ยืนยัน ให้คงสถานะ proof หรือเว้นข้อมูลนั้นโดยไม่สร้างข้อเท็จจริงเอง

ดำเนินการผลิต assets และ PDF proof ในขอบเขตที่ผู้ใช้ยืนยัน โดยไม่ขออนุมัติซ้ำและไม่แก้ application code

ข้อจำกัดยังคงอยู่: crop เซ็ตต้นทางกว้างเพียง 236–352 px รายละเอียดอักษร/ลวดลาย/พอร์ตที่ AI สร้างใหม่จึงไม่ใช่หลักฐานสเปกหรือความเหมือนสินค้าจริงทุกจุด ภาพเต็มความกว้าง A4 มีประมาณ 131 ppi ซึ่งต่ำกว่าเป้าหมาย 150–200 ppi ในข้อ 7 และไม่ถึง 300 ppi สำหรับงานพิมพ์ ไม่มี printer ICC/output intent/bleed หรือ PDF/X preflight จึงส่งเป็น **creative proof สำหรับตรวจรูปแบบ** ไม่ใช่ print-ready หรือพร้อมเผยแพร่เชิงพาณิชย์ ราคา สต็อก สิทธิ์ภาพ โลโก้และช่องทางติดต่อยังต้องยืนยันก่อนฉบับเผยแพร่

พบความขัดแย้งเดิมใน canonical BOM และเส้นทางภาพ จึงใช้ catalog ต้นทางสำหรับฉบับ proof และบันทึก [RCA แยก](../../.brain/rca/RCA-CATALOG-ASSET-SOURCE-VALIDATION-2026-08-30.md) โดยไม่แก้ pipeline/master และไม่ใช้ข้อมูลที่ขัดกันสร้างสินค้าหรือองค์ประกอบชุดใหม่
